## 一、AI 部分的骨架

- SDK：`coze-coding-dev-sdk ^0.7.24`，`LLMClient + Config + HeaderUtils`
- 调用方式（每个接口都一样）：
  ```ts
  const config = new Config();
  const forwardHeaders = HeaderUtils.extractForwardHeaders(request.headers);
  const client = new LLMClient(config, forwardHeaders);
  const stream = client.stream(messages, { model: MODEL, temperature: 0.7, caching: 'enabled' });
  ```
  即**把浏览器请求头转发给 SDK**，由平台运行时身份鉴权 —— 所以平台内不用管令牌
- 模型：`doubao-seed-2-0-pro-260215`；评分 `temperature: 0.1`，对话 `0.7`；都开 `caching: 'enabled'`（前缀缓存）
- SSE：`ReadableStream<Uint8Array>` + `Content-Type: text/event-stream`

### SDK 能不能脱离扣子平台（查包内 .d.ts 确认）
```ts
export interface CozeConfig { apiKey?: string; baseUrl?: string; modelBaseUrl?: string; ... }
export declare class Config { apiKey; baseUrl; modelBaseUrl; runtimePlatform; projectRuntimeAuth; usesUserRuntimeAuth() }
```
- 默认 baseUrl：`https://integration.coze.cn`（扣子集成网关）
- **可以自己传 apiKey + baseUrl** → 理论上能接方舟 / 自建网关；但网关是否接受该 key 需实测
- 不传时走 `projectRuntimeAuth`（平台注入）→ 本地 next dev 没有这套头，**默认不通**

## 二、最值得抄的一条：评分是「程序算分，模型只写评语」

```ts
// src/lib/agent/prompts.ts
export const REPORT_FEEDBACK_PROMPT = `你是实验伴学导师。下面是某学生实验报告的确定性脚本评分结果
（7个维度得分与缺失项清单，数值已由程序算好，禁止改动任何分数）...`
```
- 分数由**确定性脚本**（rubric）算，7 个维度 + 缺失项清单
- 模型只负责把分数翻译成人话：strengths / weaknesses / next steps
- 好处：分数可复现、可解释、不飘；模型输出短 → **快**（这也解释了为什么他们那边评分不慢）

我们 chem-lab 现在是反的：模型给 score、规则只做封顶 → 分不稳、输出长、慢。

## 三、助教的三个机制（我们目前没有）

1. **分阶段 prompt**：`STAGE_PROMPTS` 覆盖 intro / variable / event / dependent / questionnaire / sample / order / analysis，每阶段 `{system, opening}`
2. **会话状态机**：`session.ts` 按 `studentNo + stage` 存 SessionState，`buildLlmMessages` 组上下文
3. **规则熔断** `verdict.ts`：
   - `parseVerdict` 从输出尾部剥掉 `[CONTINUE]/[NEXT]/[FINISH]` 控制标记，学生看不到
   - `checkRuleFuse`：学生挫败（不知道/放弃/烦死了）、索要答案（HINT_REQUEST）、乱语（单字/语气词/复读 n-gram）→ 强制收敛
   - `MIN_GUIDANCE_ROUNDS = 3`：至少引导 3 轮才允许推进 —— "引导不代答"是写死在规则里的

## 四、对 chem-lab 的结论

| 事项 | 他们 | 我们 | 建议 |
|---|---|---|---|
| 评分算分 | 脚本算 7 维，模型只写评语 | 模型给分 + 规则封顶 | **改过来**：`lib/rules` 已有打分，改造 `/api/plan/assess` |
| 前缀缓存 | `caching: 'enabled'` | 无 | 固定前缀（规则/人设）前置，省 token 提速 |
| 助教上下文 | 会话状态机 | 每问独立 | 复用 conversation_id 或在服务端存 session |
| 引导纪律 | 熔断 + 最少 3 轮 | 无 | 我们 `lib/engine.ts` 已有步骤，可挂同类熔断 |
| 凭据 | 平台运行时头转发 | PAT（30 天） | **部署在扣子编程 → 走平台鉴权，彻底不用管令牌有效期** |
