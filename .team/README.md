# .team —— 多 agent 协作的落盘区

> 为什么存在：Agent Team 会并行开 4~10 个队友，每个队友的上下文是**独立且有限**的。
> 对话会被压缩、会被截断、会注意力偏移。**所以结论必须落盘，不能只活在对话里。**

## 一条铁律

**没写进 `.team/` 的结论 = 没发生过。**
Lead 汇合时不靠"回忆对话"，只读这里的文件。

## 目录约定

```
.team/
├── README.md           # 本文件（机制）
├── notes/<角色>.md      # 进展日志：每完成一小块就追加（最重要）
├── handoff/<角色>.md    # 交接包：角色结束时写，下一个人只读这个
├── tasks/<名字>.md      # 任务卡：**谁认领谁自己写**，Lead 不派活
└── DECISIONS.md        # 决策记录：谁定的、为什么、影响谁（Lead 维护）
```

**分工不是 Lead 写死的。** Lead 只说目标、硬约束、验收标准，拆分方案由团队自己提、自己认领、自己写任务卡。
Lead 只在"两个人抢同一个文件"时叫停，在"跨角色接口"上定稿。

## 每个队友的固定动作

1. **开工前**：认领任务 → 写自己的 `tasks/<名字>.md`（目标 ≤5 条、独占哪些文件、验收标准）→ 读 `DECISIONS.md`。
   不要读别人的 notes（浪费上下文）。
2. **每完成一个可验收小块**：立刻往 `notes/<你的角色>.md` **追加**一条，格式固定：

```markdown
## 2026-10-20 18:05 · 完成：规则 R1 判定
- 做了什么：lib/rules/exp09.ts 加 rinse 规则
- 证据：`npx vitest run lib/rules/exp09.test.ts` → 3 passed
- 改了哪些文件：lib/rules/exp09.ts, lib/rules/exp09.test.ts
- 下一步 / 阻塞：等 A 轨道的 engine 接口
```

3. **结束前**：写 `handoff/<角色>.md`（≤20 行）：做完了什么、没做完什么、下一个人从哪接着干、坑在哪。
4. **不许**把结论只写在对话回复里；回复里只给"已落盘到 X 文件"。

## Lead 的动作

- spawn 前：写 `tasks/<轨道>.md`，里面只放该角色需要的东西（接口契约 + 验收标准），**不要贴大段代码**，给路径。
- 汇合时：`git diff --stat` + 读 `notes/*.md` 的**末尾几条**，不重读全文。
- 争议/取舍：写进 `DECISIONS.md` 一行，注明影响范围。
- 上下文吃紧时：先让队友写 handoff，再 `interrupt` 换新队友接着干——**换人不换文件**。

## 上下文纪律（防截断/防偏移）

- 单次任务卡目标 ≤ 5 条，超过就拆轨道。
- 代码不贴进上下文：给文件路径 + 行号，让 agent 自己读。
- 队友只读自己轨道相关的文件；跨轨道接口看 `tasks/` 里的契约段。
- 同一角色连续工作超过约 8 轮没有落盘 → Lead 强制要求先写 notes。
