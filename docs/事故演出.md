# 事故演出：中途炸 + 炸完再出说明（t_2d92eaa7）

用户口径（2026-10-23）：**「事故在动画中途炸（错误演示面板复用同一套资源），炸完再出说明。」**

## 一条时间线，两个入口合一

```
0 ──── lead 720ms ────┬──── hazard 900ms ────┬──── settle 540ms ──── 2160ms
起手错操作（倒液/加热/搅洗/捅洗）   中途出事（裂/炸/暴沸…）     余波归位
                    ↑ cue: "impact"                        ↑ cue: "settle"
```

- 入口只有一个：`SceneStage` 暴露的 `SceneActionApi.playIncident(plan)`（内部仍走 `playAction`，
  和洗涤/搅拌/转移完全同一条底层）。
- 参数推导只有一个纯函数：`planIncident()`（`components/exp/scene/actions/incident-plan.ts`）。
- 画面只画在实验台那一个 SVG 里：`buildIncident()`（`actions/incident.ts`）+ `hazardArt()`（`actions/incident-art.tsx`），
  坐标来自 `anchorOf(vesselId)`（和倾倒动画同一份器皿几何），液体用器身 clipPath + `--scene-*` token。
- 真操作与错误演示的差别只有一个参数：`runIncident(plan, { commit })` ——
  真操作传 `commit: () => choose(choiceId)`（播完才扣分/出事故条），演示不传（状态不动）。

## 错误演示面板现在只是「触发器」

`TrapPanel` 点击 → `planIncident()` → `runIncident()` → 台面上演事故 → 播完才挂说明。
旧实现（点一下立刻弹 3 行说明 + 覆盖层小场景）已删除；`device-accident` / `heavy-metal` 这两类
不在器皿上发生的事故仍走覆盖层特效，但说明同样等画面播完再出。

## 证据（三帧 × 两场景 + 真操作对照）

固定时间点：`mid ≈ 410ms`（起手动作进行中）、`impact ≈ 1030ms`（炸开瞬间）、`note ≈ 2820ms`（说明出现）。

| 场景 | 动画中 | 爆炸瞬间 | 说明出现 |
|---|---|---|---|
| A 加热空容量瓶（陷阱 `step1-oven`，L2 玻璃炸裂） | `docs/incident-frames/exp01-oven-1-mid.png`（火焰在器底、瓶内无液体、**没有说明卡**） | `docs/incident-frames/exp01-oven-2-impact.png`（裂纹 + 碎玻璃 + 蒸汽 + 冲击环、**没有说明卡**） | `docs/incident-frames/exp01-oven-3-note.png`（L2 · 数据作废 + 「为什么 / 怎么办」两行） |
| B 玻璃棒捅洗容量瓶（陷阱 `step1-poke`，L3 瓶壁裂纹） | `docs/incident-frames/exp01-poke-1-mid.png`（玻璃棒插进瓶口） | `docs/incident-frames/exp01-poke-2-impact.png`（裂纹从撞击点长开） | `docs/incident-frames/exp01-poke-3-note.png` |

三帧都能看到「同一个台面、同一台容量瓶、同一套玻璃/液体画法」：器皿位置不变、液面不跳、
没有第二个小场景、没有弹窗遮画面。

## 帧率（事故动画期间实测，1 次冷启 + 6 次预热）

浏览器实机（Browser Use 自带 Chromium，180Hz 面板），rAF 采样整段 2.1s：

| 运行 | p50 | p95 | max | >33.4ms 帧 |
|---|---|---|---|---|
| 冷启首次（dev 首次挂载） | 5.3ms | 6.1ms | 22.0ms | 0 |
| oven ×3 | 5.3ms | 6.1ms | 21.9 / 17.0 / 21.3ms | 0 |
| poke ×2 | 5.3ms | 6.2ms | 17.1ms | 0 |

结论：预热后单帧最差 22ms（≈45fps），常见 5.3ms；**没有一帧掉到 30fps 以下**。
事故段仍是「拖动期间零 setState、rAF/WAAPI 驱动」：动画期间 React commit = 0，
只有 `playIncident` 开始和播完各一次状态变更。

## 已知遗留（不在本卡范围，另开任务）

`buildRinse` / `buildTransfer` / `buildStir` 的液体层把 `transform` 写在了 `clipPath` 的子 `path` 上，
在这块台面 SVG 里 Chrome 会忽略该裁剪（实测：洗涤/转移时水层溢出器皿外）。本卡的事故层已改成
「clipPath 用局部坐标 + 外层 `<g transform>`」（和 `GlassVessel` 一致），并已验证裁得干净；
上述三个动作文件是同一处旧写法，另行处理。
