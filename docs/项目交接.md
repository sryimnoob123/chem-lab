## 三、怎么把它跑起来

### 1. 本地开发（改代码用）
```powershell
cd E:\workspace\public\NOBBBB\chem-lab
npm run dev -p 3002        # 首次要设 PGLITE_DIR=.pgdata-dev-xxx
```
访问 **http://localhost:3002** —— 注意必须用 `localhost`，**不要用 127.0.0.1**（会导致 hydration/HMR 异常）。

### 2. 本地生产模式（交付验收用，也是最快的验证方式）
```powershell
# ① 先停 3001（构建会锁 .next 目录，不停会 EBUSY）
$c = Get-NetTCPConnection -LocalPort 3001 -State Listen -ErrorAction SilentlyContinue
if ($c) { ($c | Select-Object -ExpandProperty OwningProcess -Unique) | % { Stop-Process -Id $_ -Force } }

# ② 构建
npm run build

# ③ 把静态资源拷进 standalone（不拷 = 页面用旧代码、点击没反应）
Copy-Item .next\static .next\standalone\.next\static -Recurse -Force
Copy-Item public .next\standalone\public -Recurse -Force

# ④ 起服务
$env:PORT="3001"; $env:HOSTNAME="127.0.0.1"
$env:PGLITE_DIR=(Join-Path (Get-Location).Path ".pgdata-prod2")
node .next\standalone\server.js
```
> 也可以直接用 `scripts/restart-prod.ps1`（但它可能跑完不退出，看到 200 就手动关掉）。

### 3. 部署到扣子
```powershell
# 改了代码先推 GitHub（扣子部署会拉 main）
git push origin main

# 触发部署（返回 status: Pending，然后轮询）
coze code deploy 7698969999712714767 --format json
coze code deploy status 7698969999712714767 --format json   # Succeeded 即完成
```
**关键坑**：容器文件系统**只读**，不能让代码回退到 PGlite 本地文件模式，必须注入 `DATABASE_URL`：
```powershell
coze code env set DATABASE_URL "postgresql://postgres:qxzIR7mVm5g37p0UO5@cp-nifty-moon-36f7d89b.pg2.aidap-global.cn-beijing.volces.com:5432/postgres?sslmode=require" -p 7698969999712714767
```
（`{{PASSWORD_xxx}}` 是平台密钥占位符，部署时会被替换成真密码）

### 4. 往扣子的数据库灌数据
```powershell
# CLI 的 --file 不支持多语句，用这个分批脚本（每批 6 条 + 失败重试）
node scripts/coze-db-apply.mjs 7678667938580168745 db/migrations/0001_init.sql
node scripts/coze-db-apply.mjs 7678667938580168745 db/seed-experiments.sql
node scripts/coze-db-apply.mjs 7678667938580168745 db/seed-students-40.sql

# 校验
coze code db query --db-id 7678667938580168745 --sql "SELECT count(*) AS n FROM experiments;" --format json
```
> 注意 CLI 经常 `fetch failed`（网络抖动），脚本已内置重试；手动查时多试几次。

## 八、踩过的坑（血泪版）

1. **改完 build 前必须停 3001** —— 否则 `rmdir .next\standalone` 报 EBUSY。
2. **build 后必须把 `.next/static` 和 `public` 拷进 `.next/standalone`** —— 不拷就是"旧代码/点了没反应"。
3. **容器只读** —— 扣子线上没有 `DATABASE_URL` 时，代码会回退 PGlite 并尝试 `mkdir .pgdata` → `EROFS` → 全部接口 500。必须设 `DATABASE_URL`。
4. **`coze code db query --file` 只吃单语句** —— 多语句要么拆开，要么用 `scripts/coze-db-apply.mjs`。
5. **`coze code message status` 会卡在 `processing`** —— 别傻等，用 `coze code message history -p <id> --format json` 直接读历史问答。
6. **中文文件只能用 `write`/`edit` 工具改** —— 用 PowerShell 的 `Set-Content`/`Add-Content` 会把中文注释写成乱码并合并行（曾经把 `lib/db/index.ts` 写坏）。
7. **访问地址必须 `localhost`** —— `127.0.0.1` 会破坏 hydration/HMR。
8. **Reveal 入场动画靠 IntersectionObserver** —— 截图验收前要先滚到底再滚回顶部，否则首屏外的行 `opacity: 0` 拍不到。
9. **`.preview` 是 gitignore 的** —— 拉代码后如果扣子报缺文件，参考 `AGENTS.md` §0.1 重建。
10. **Windows 上 `spawn("coze")` 找不到命令** —— 它是 `.ps1`/`.cmd` 包装，要么用 `shell: true`，要么直接 `node E:/TOOLS/node/node_modules/@coze/cli/bin/main`。
