### 4.1 第一步：推到 GitHub

```powershell
git add -A
git commit -F .git/COMMIT_MSG_TMP.txt   # 中文提交信息必须走文件，直接 -m 会被 PowerShell 吃掉

```

- **`-m "中文"` 会失败**（PowerShell 把中文引号当参数分隔），必须写进文件用 `-F`。
- **`http.sslBackend=openssl` 会报证书错**（`unable to get local issuer certificate`），用 **`schannel`** 成功。
- 走代理必失败，要显式 `-c http.proxy= -c https.proxy=` 清掉。

### 4.2 第二步：让扣子容器拉到最新代码

**`coze code repo pull` 是坏的**——它返回 `{"status":"success"}` 但代码根本不变，部署出来的 `commitHash` 永远停在旧值。**不要信它，也不要反复重试。**

唯一有效的办法是**让扣子项目的 AI 在容器里执行 git 命令**：

```powershell
coze code message send "请只执行这一条：cd /workspace/projects && git fetch origin main && git reset --hard origin/main && git log --oneline -1。不要修改文件，不要部署。" -p 7698969999712714767 --wait --format json
```

- 容器里的仓库会有**本地分叉**，直接 `git pull` 会报 `Need to specify how to reconcile divergent branches` 然后中止 → 必须用 `git reset --hard origin/main` 强制同步。
- 成功标志：输出里有 `HEAD is now at <你的 commit>`。

### 4.3 第三步：部署

## 7. 已知坑（踩过的，别再踩）

| 坑 | 真相 |
|---|---|
| `coze code repo pull` | **假的成功**，代码不变。必须走 `coze code message send` + `git reset --hard origin/main` |
| `git commit -m "中文"` | PowerShell 会吃掉中文引号 → 用 `-F 文件` |
| `git push` 走代理 | 必失败 → `-c http.proxy= -c https.proxy=` |
| `sslBackend=openssl` | 证书报错 → 用 `schannel` |
| `npm run build` 后不跑 `restart-prod.ps1` | 整页无样式，所有选择器失效 |
| PowerShell 写中文文件 | 会双重编码。中文内容**只能用 write/edit 工具或 node `fs.writeFileSync(p, s, "utf8")`** |
| PowerShell 读 UTF-8 中文显示乱码 | 是**读取侧**问题（`Get-Content` 按 GBK 解码），文件本身正常。用 read 工具看 |
| `Get-Content -Encoding UTF8` | 本机 pwsh 不支持该参数 |
| `grep` / `rg` 在 pwsh | 不可用 → 用 grep 工具 |
| `NextActionCard` 文案 >18 字 | 会被 `clip()` 裁掉，看着像话没说完 |
| CSS Modules 哈希 | `[data-dragging]` 这类选择器要写 `:global(.ix)` 才匹配得到 |
| 大热区遮挡 | `demo-scene-drop-flask` 覆盖整个台面且盖在 SVG 之上，`elementFromPoint` 只会拿到它 → 找器皿必须用 `elementsFromPoint` |
| `path[d="M88 604 H260"]` | 被 `pour.tsx` 的液面抬升动画按选择器锁定，改 `d` 会让倒入时液面不动 |
