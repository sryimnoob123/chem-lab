## 1. 启动

> **唯一正确的生产启动路径**（`next.config.ts` 是 `output: "standalone"`）：

```powershell
# 0) 一键启动（推荐）：双击 start-chem-lab.bat
#    它会自动 build、拷静态资源、后台起 3001、轮询到 200 后打印地址

# 1) 首次依赖
npm install

# 2) 本地数据库（首次，或数据目录损坏后重建）
$env:PGLITE_DIR = (Join-Path (Get-Location).Path ".pgdata-prod2")
npm run db:init      # 建表 + 10 个实验定义
npm run db:demo      # 播种 40 人的演示班级（可加 -- --purge 清空重播）

# 3) 生产构建（单次，cpus: 4，约 18 秒）
npm run build

# 4) 拷静态资源（每次 build 后都要做一次）
Copy-Item .next\static .next\standalone\.next\static -Recurse -Force
Copy-Item public .next\standalone\public -Recurse -Force

# 5) 起服务（必须显式给 PGLITE_DIR 和 PORT）
$env:PGLITE_DIR = (Join-Path (Get-Location).Path ".pgdata-prod2")
$env:PORT = "3001"
$env:HOSTNAME = "127.0.0.1"
node .next\standalone\server.js
```

**访问地址：`http://localhost:3001`**

### 为什么不能用 `npm start`

`next start` 不支持 `output: "standalone"`——Next 会打印警告，而且**嵌入式 PGlite 的查询会直接 `Aborted()`**（表现为端口能打开、页面能开，但登录接口 500）。必须用 `node .next/standalone/server.js`。

### 为什么别用 `127.0.0.1`

- 开发态（`npm run dev`）下，Next 16 会把 `127.0.0.1` 与 `localhost` 判为**跨源**，HMR 被拦、页面不水合，看起来就是一片空白。
- 生产态用 `localhost:3001` 访问最稳；服务端绑定 `HOSTNAME=127.0.0.1` 只影响监听地址，不影响浏览器访问 `localhost`。

### 端口与进程

- 默认端口 **3001**；被占用时启动脚本**只提示、不硬杀**（避免误杀别的东西）。
- **禁止两个实例共用同一个 `PGLITE_DIR`**：PGlite 是单写独占，第二个实例会 Abort 或把数据目录写坏。

## 4. 已知问题（按严重度）

### 高（演示时会被问到）

1. **纯拖拽/点选投放本身不进 run 时间线**——投放只更新界面与 `inputMode`，真正写进 `events` 的是下一个动作。要看"每次投放都留痕"，需要新增审计事件入口。
2. **一键演示里的结果页取"该学号最新一条已完成记录"**，不一定是演示刚做的那次（演示模式只读，不产生新 run）。

### 中

3. **实验页「点选」时器皿的"可投放高亮"未生效**（`/scene-preview` 正常）。投放能成功、文案逐字正确，只是中间态视觉没接上。
4. **键盘路径的自动验收是弱断言**——按 `1` 后步号未推进时靠事件条是否有内容判定，需人工确认一次。
5. **只有实验 09 可进入**，其余 9 个实验有定义但未接通操作台（列表里显示为锁定）。

### 低

6. 演示视频只有 `.webm`（Playwright 自带 ffmpeg 缺 mp4 封装器），微信可能无法预览；Chrome/飞书桌面可播。
7. `/demo` 与 `/scene-preview` 是内部调试页，不建议写进对外材料。
8. 报告里的"预习 10%"来自前测，目前没有独立前测页，故常显示 0 分（公式本身正确）。

## 6. 运维注意

- **启动/停止统一走脚本**：双击 `start-chem-lab.bat` 起服务（后台 3001、日志在 `logs/server.log`、轮询到 200 才打印地址）；双击 `stop-chem-lab.bat` 停止。不要手工 `npm start`（见 §1 说明）。
- **端口被占时脚本只提示不硬杀**：会打印占用进程的 PID 和端口，让你自己决定，避免误杀别的服务。
- **不要用 `Stop-Process -Force` 硬杀服务进程**。PGlite 是嵌入式 WASM 数据库，被强杀会 `Aborted()`，数据目录损坏后表现为**登录接口 500**（端口却还是 200，极易误判成"页面没问题"）。正确做法：用 `stop-chem-lab.bat` 优雅停止。
- **数据目录损坏后**：保留现场（重命名为 `.pgdata-broken-<时间>`，已被 `.gitignore` 忽略）→ 用**新的** `.pgdata-prod3` 之类目录 → `PGLITE_DIR=<新目录> npm run db:init && npm run db:demo` → 重启服务。PGlite 损坏目录一般无法原地修复。
- **同一 `PGLITE_DIR` 只能被一个实例占用**：PGlite 单写独占。要并行验证（例如 3002/3003），必须**复制一份数据目录**给另一个实例。
- `next.config.ts` 已设 `cpus: 4`、`vitest.config.ts` 已设 `maxWorkers: 4`，用于在本机 16 GB 内存下避免构建/测试把内存打爆。
- **构建只跑一份，不要并发多份 build**；两次 build 之间先停服务，避免 `.next` 被同时读写。
- **PGlite 数据目录不能靠复制复用**（实测）：把 `.pgdata-prod2` 复制成 `.pgdata-test` 后起 3002，服务能开、首页 200，但登录接口 500（`Aborted()`）。要并行验证两个端口，唯一办法是**各用各的新目录重新 `db:init` + `db:demo`**。
- 启动脚本参数：`start-chem-lab.bat -Port 3002 -DbDir .pgdata-test -SkipBuild -NoOpen`
  - `-SkipBuild`：跳过构建（产物已最新时用，省 20 秒）
  - `-NoOpen`：不自动开浏览器
  - `-DbDir`：指定数据库目录，默认 `.pgdata-prod2`
- 日志：`logs\server.log`（标准输出）、`logs\server.err.log`（错误）、`logs\server.pid`（进程号，`stop-chem-lab.bat` 用）。`logs/` 已进 `.gitignore`。
