# 演示钩子与覆盖表（2026-10-21）

> 口径：演示 = **脚本驱动真实 UI**（不另做一套假页面）。观众看到的点击、反馈、扣分、报告，
> 都是学生真做时会走的那套组件。本文是「钩子清单 + 覆盖表 + 时序规则」的单一来源。
> 归属：`lib/demo/**` 由 demo-flow 维护；`components/**` 的钩子由对应 owner 接线（见 §5）。

## 1. 播放链路与数据流

```
DemoLaunch（右上角「一键演示」）
  → DemoOverlay（浮层，Esc / 从头再演 / 退出）
    → DemoStage（iframe src = script.page + "?play=demo"）
      → DemoDirector（按 script.steps 逐步执行）
        → 被演示页 app/exp/[id]/workbench.tsx（真实状态机 + 真实反馈组件）
```

- `?play=demo` → `demoReadonly=true`：**不创建 run、不写库**，交卷直接跳 `/exp/[id]/report?demo=1`。
- 退出浮层 = iframe 卸载，页面状态与演示注入的 DOM 全部丢弃；演示中途停播也不残留。
- 演示顺序的唯一来源：`lib/demo/scripts/index.ts` 的 `DEMO_SCRIPTS`，`DEMO_ORDER` 由它派生。
  前 7 场仍是原有标准流程（home/login/catalog/exp09/report/fx/teacher），10 个实验脚本追加在后，
  **默认开场仍是 home，原路径不变**。

## 3. 每个操作的可见动效（director 统一施加，脚本不用逐条写）

| 阶段 | 动效 | 参数 | 实现 |
|---|---|---|---|
| 位移 | 光标沿 `translate3d` 飞到目标中心 | 点击 320ms、其它 460ms，`cubic-bezier(.23,1,.32,1)` | `cursor.moveTo` |
| 目标高亮 | 目标 2px 河大蓝描边亮一下再复原 | 180ms | `cursor.outline(el,"river")` |
| 按下反馈 | 光标 `scale(1→.86→1)` + 一圈 ripple | 140ms + 420ms 波纹 | `cursor.press` |
| 结果反馈 | 以目标为圆心再扩散一圈：做对 `jade`、出错 `danger`、普通 `river` | 420ms | `cursor.ringAt` + 读 `demo-feedback-ok-N / -fail-N` |
| 字幕 | 动作完成、结果条出现后才播该动作解说 | 见 §4 | `onCaption` 在 `runStep` 之后 |
| 页面自带反馈 | 器皿脉冲/抖动、读数 `.ix-pop`、`L3/L4` 事故特效、结果条两段式、下一步卡片 | 由 workbench/组件负责 | 点击真实按钮即触发 |

## 4. 字幕与操作时序规则（定稿：先操作，后字幕）

1. **动作类步骤**（click/type/scroll/highlight）的 `text` 一律在**动作执行完 + 结果反馈出现后**播出；
   观众先看到"发生了什么"，再听"为什么"。
2. **caption / wait 步骤**是段落导语（还没有任何动作发生），立即播；
   用于"第 N 步 · 标题"和转场说明。
3. 需要精确等结果时用 `kind: "waitFor"`（新 step kind）：轮询目标 `data-demo-id` 出现/可点，
   最多 `timeout`（默认 3000ms，超时只跳过不中断），之后再播字幕。
   - **拖拽路径注意**：workbench-ux 已把 drop 后的 dispatch 延后到倒入动画 700ms 播完。
     若脚本走拖拽/投放，必须在投放后 `waitFor demo-feedback-ok-N`（或至少 `wait ≥800ms`）再继续，
     否则会抢跑、截断动画。当前 10 个实验脚本走点选路径，同样用 `waitFor` 兜住结果条，因此不抢跑。
4. 点击步骤内部还固定等 380ms 观察窗（够 React 一帧 + 结果条入场 260ms）再判定做对/出错。

## 5. 钩子清单

### 5.1 脚本使用的既有钩子（已存在，无需接线）

| 钩子 | 所在 | 用途 |
|---|---|---|
| `demo-op-stepN-*` | 每步 `choices[].demoId` | 正确动作 / 陷阱动作（陷阱也能作为负反馈演示） |
| `demo-retry-N` | `ResultBar` | 失败后「重做本步」 |
| `demo-finish` | 工作台顶栏 | 交卷 → 报告 |
| `demo-feedback-ok-N` / `demo-feedback-fail-N` | `ResultBar` 根节点 | 判定结果条已出现 + 决定反馈环颜色（只读，不点击） |
| `demo-feedback-detail` | 失败原因折叠区 | 失败三行（错在哪/为什么/怎么改） |
| `demo-other-ways` | 「其他做法」折叠区 | 陷阱按钮所在容器 |
| `demo-mode-*` / `demo-page-*` / `demo-home-*` / `demo-login-*` / `demo-catalog-*` / `demo-report-*` / `demo-teacher-*` | 各页面 | 前 7 场标准流程脚本 |

**折叠区处理**：陷阱按钮在「其他做法」`<details>` 里且默认收起。director 在点击前会
**自动展开目标所在的所有 `details`**（`revealAncestors`），所以不需要给 `<summary>` 加钩子也能演。

### 5.2 建议补的钩子（可选，不阻塞；需 Lead 分派给对应 owner）

| 建议钩子 | 文件 | 加在哪 | 补了以后演示能多做一步 |
|---|---|---|---|
| `demo-other-ways-toggle` | `app/exp/[id]/workbench.tsx` | 「其他做法」`<summary>` | 让"展开其他做法"成为被光标点击的可见动作，而不是 JS 直接改 `open` |
| `demo-step-dot-N` | `app/exp/[id]/workbench.tsx` / `StepTimeline` | 顶部步骤刻度 | 演示可高亮"现在走到第几步"，与字幕同步 |

> 以上三项都不阻塞现有脚本：没有它们，10 个实验的演示仍能完整跑通。

## 6. 失败分支与重试

- 脚本在某个中间步先点一个**陷阱动作**（`role: "trap"`，均为 L3，带 `/` 后的特效键）：
  结果条出现 `demo-feedback-fail-N`（三行 + 等级 + 扣分），L3/L4 播放 `FxByKey` 事故特效。
- 接着点 `demo-retry-N`：`workbenchReducer` 的 `retry` 用 `stepStart` 快照回滚到该步开头，
  `event=null`、`retrySeq+1`，**错误仍记在时间线里**（只记过程，不阻断继续操作）。
- 重做后按该步正确顺序继续点，直至交卷。**L4 终止类陷阱不入脚本**（终止后不能本步重做）。

## 7. 退出 / 脏数据

- `DemoDirector.stop()` → `cursor.destroy()` 删除光标、波纹、反馈环、演示边框（按 `data-demo-fx` 全清）。
- 浮层关闭 = iframe 卸载；`play=demo` 下 `demoReadonly=true`，全程不 POST `/api/runs/*`，不落库。
- 演示中途退出不写 PGlite / 数据库；脚本里也没有任何直接写存储的调用。
