## 真 PostgreSQL 现状（实测，别搞混）
- 正在跑的服务 `postgresql-x64-17`：`AUTO_START`，**数据目录在 `C:\Program Files\PostgreSQL\17\data`**，监听 5432。这是机器上本来就有的实例。
- `E:\TOOLS\pgsql`：另用 winget 装的一份 PostgreSQL 17 二进制（17.11-5），**没有 data 目录、也没注册自己的服务**，只作备用/升级用。
- 结论：要连真库就直连 `127.0.0.1:5432`；想给 E 盘那份单独初始化，先 `initdb -D E:\TOOLS\pgsql\data` 再用 5433 起，避免和现有服务抢端口。

## 为什么开发用 PGlite
扣子给的是托管 PostgreSQL，部署时**只同步 schema、不同步数据**。所以本地要做的是把 schema 和迁移做干净，而不是模拟生产数据量。
PGlite 与真 PG 同引擎，SQL 一致；切生产的改动点只有 `lib/db/index.ts` 一处（换成 pg 驱动 + 平台注入的连接串）。

## 踩过的坑（按遇到顺序，下次直接跳过）

### 1. PGlite 在 Next 16 + Turbopack 下报 `Received an instance of URL`
现象：页面显示「读取失败」，dev 日志里是
`unhandledRejection: TypeError: The "path" argument must be of type string ... Received an instance of URL`。
修法两条一起上（缺一不可）：
- `next.config.ts` 加 `serverExternalPackages: ["@electric-sql/pglite"]`（不打进 server bundle）
- `lib/db/index.ts` 用 `path.resolve(process.cwd(), ...)` 传**绝对路径**

### 2. Next 16 会自己改 `tsconfig.json`
启动时强制 `jsx: "react-jsx"` 并往 `include` 里加 `.next/dev/types/**/*.ts`，还会尝试写 `AGENTS.md`（已存在就跳过，我们那份没被覆盖）。**别手改回去**，它每次都改。

### 3. ESLint 9 没有 `next lint` 了
`npm run lint` 原来是 `next lint`，跑起来报找不到配置。修法：加 `eslint.config.mjs`（flat config，从 `eslint-config-next/core-web-vitals` 和 `/typescript` 展开），脚本改成 `eslint .`。

### 4. 「读取失败 + EADDRINUSE」组合拳
先起的 dev 进程 kill 之后没死透，还占着 3000，并且手里握着被 `rm -rf .pgdata` 删掉的旧数据库 → 页面一直「读取失败」，而新 dev 起不来只报 `EADDRINUSE`。
排查顺序：`netstat -ano | grep ":3000 .*LISTENING"` 拿 PID → `taskkill /PID <pid> /F` → 再起。
判据：新进程日志里应该有 `Ready in`；只有 EADDRINUSE 说明根本没轮到它。

### 5. `npx skills add` 的落点不在 Hermes 里
它装到 `<项目>/.agents/skills/`（并 symlink 给 Claude Code），Hermes 读的是 `profiles/<档>/skills/`，要手动拷过去。
好消息：`.agents/skills` 正是 dsh 技能路径的 rank 200，也和 Codex 共享——以后想让 dsh 原生吃到，装到项目 `.agents/skills` 就行。

### 6. PGlite 数据目录是独占的
dev server 开着的时候跑 `npm run db:init` 会失败或互相锁。规矩：**先停 dev → 初始化 → 再起**。
