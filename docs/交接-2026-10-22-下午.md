## 2. 倒入动画到底改了什么

用户原话（2026-10-22）：「瓶子到的时候瓶口朝向有点问题」「要真的像被人举着倒」。

**问题**：旧实现 `transform-origin: 50% 88%`（挂瓶底）+ `TILT_DEG = -58`。绕瓶底逆时针转 58°，瓶口甩到**左上**，而落点在**右下** —— 视觉上是"瓶子歪了"，不是"在倒"。

**现在的实现**（`components/exp/scene/pour.tsx`）：

```ts
const TILT_DEG = 118;                    // 方向按瓶从哪侧来取 ±
const MOUTH_TO_BOX = { x: 15, y: -8 };   // 瓶身左上角相对瓶口中心
const MOUTH_GAP = 68;                    // 瓶口悬在液面上方的高度
const STREAM_DELAY = DROP_START - 60;    // 370ms
const STREAM_GROW_MS = 220;
const STREAM_MS = 560;
```

配套 CSS（`components/exp/scene/scene.module.css`）：

```css
.pourBottle { transform-origin: 50% -8px; }  /* 挂瓶口，绕口旋转瓶口不动 */
```

时序（`TOTAL_MS = 1160`，与 `drop-resolve.ts` 的 `POUR_MS` 对齐）：

| 时间 | 动作 |
|---|---|
| 0ms | 瓶子从试剂架飞到器皿上方（290ms 缓出） |
| 290ms | 绕**瓶口**倾转 118°（180ms）——瓶身甩下去、瓶口不动 |
| 370ms | 连续液柱从瓶口竖直落下（scaleY 生长 220ms，持续 560ms） |
| 430ms | 3 颗液滴沿同一条竖线错开下坠 |
| 620ms | 落点涟漪 |
| 640ms | 液面抬升 |
| 900ms | 瓶子飞回架上淡出，液柱同步收尾 |

**关键约束**（别改坏）：

- 液柱只用 `scaleY` 生长，**不要换成动 height** —— 会逐帧重排，且中间会出现"断成几颗珠子"。
- `.pourBottle` 的 `transform-origin` 必须跟着 `MOUTH_TO_BOX` 走。改了瓶身尺寸就要同步改这两个值，否则瓶口和液流起点对不上。
- 液面抬升锁的是 `rect[y="604"]` 和 `path[d="M88 604 H260"]`，**这两个选择器不能动**（`path` 的 `d` 尤其不能改）。

## 5. 推送与线上同步（今天踩了新坑）

### 5.1 GitHub 推送：hosts 里有 Steam++ 残留

`git push` 报 `Failed to connect to github.com:443`。**根因不是网络**，是
`C:\Windows\System32\drivers\etc\hosts` 第 122 行 `127.0.0.1 github.com`
（Steam++ / Watt Toolkit 残留块，第 100~140 行整片把 GitHub、Steam、Nexus 指向本机）。

hosts 是只读的（没有管理员权限写不了），所以走这个绕法：

```bash
git -c http.proxy= -c https.proxy= -c http.sslBackend=schannel \
    -c http.curloptResolve=github.com:443:20.205.243.166 \
    push origin main
```

`20.205.243.166` 是 `nslookup github.com` 拿到的真实 IP（DNS 本身是好的，是被 hosts 覆盖了）。
**有管理员权限时的正解**：把 hosts 里那几十行 `127.0.0.1 <域名>` 注释掉（`.team/fix-hosts.py` 已写好，提权跑即可）。
