# 动作液体层为什么必须「裁剪挂在不动的外层」

t_81833e85 · 2026-10-23。洗涤 / 定容 / 转移 / 搅拌 / 滴加的液体层一开始都没被器身裁住，
液体矩形会横跨台面。查下来是**两个**独立的坑，只修第一个不够。

## 结构（修好之后，三个文件都是这个形状）

```tsx
<defs>
  <clipPath id={clipId}>
    <path d={a.bodyD} />          {/* 器身路径：器皿局部坐标，任何 transform 都不写在这里 */}
  </clipPath>
</defs>

<g transform={bodyTransform(a)}        {/* translate(x y) scale(s)：把局部坐标摆到台面上 */}
   clipPath={`url(#${clipId})`}>       {/* 裁剪挂在**不动的**这一层 */}
  <g data-a="water"                    {/* 动的是这一层（WAAPI translateY 液位） */}
     style={{ transform: `translateY(${levelShift(a, level) / a.scale}px)` }}>
    <rect x={box.x - 6} y={(a.surfaceY - a.y) / a.scale} width={box.w + 12} ... />
  </g>
</g>
```

三条硬规则：

1. **clipPath 的子 path 不许带 transform**。把 `transform` 写在 clipPath 里，Chrome 在这块台面 SVG
   上会直接忽略这份裁剪 —— 液体整块画出来，横跨台面（旧写法，t_2d92eaa7 时立此存照）。
2. **clip-path 不许挂在被 translate 的那一层**。裁剪在元素的局部坐标系里生效，元素自己的
   `transform` 会把裁剪一起搬走：液面一升，瓶身轮廓跟着下移，液体就在底部 / 两侧露出瓶外。
   实测（容量瓶液位 0.62）：挂在会动那层 → 588 个命中点里 456 个落在瓶身轮廓外；挂到不动的父层 → 0 个。
3. **坐标一律器皿局部坐标**：`(x - a.x) / a.scale`、`(y - a.y) / a.scale`，`levelShift()` 的位移和
   描边宽度都要 `/ a.scale`；横向用 `liquidBox(kind)`（器皿自己的液面几何，局部坐标）而不是包围盒 ——
   包围盒 `a.w` 是从 `a.x` 起算的，液体会整体偏左 22 viewBox 单位（修裁剪后才看得出来）。

## 事故演出（incident.tsx，t_591572a5）

事故的液体层原来也是「裁剪挂在会动那层」，横向还用包围盒 `a.w`。事故液位从 base 涨到 surge
（最高 0.9）再回落，裁剪跟着液面走，瓶底那圈被裁掉、液体下缘浮在瓶底之上。现在改成和洗涤
一模一样的三层结构：`<g transform clip-path>` → `<g data-i="liquid" translateY>` → rect 用
`liquidBox(kind)`。

实测在**真实应用**（dev :3000，`/exp/exp01` 点「错误演示 → 拿玻璃棒在容量瓶里搅洗」，
WAAPI 暂停冻结一帧，再把液面推到 0.38）上做对照。命中点用 `document.elementsFromPoint`
取整叠（事故的爆心闪光/裂纹会盖在液体上，单用 `elementFromPoint` 只看得到闪光）：

| 结构 | 命中点 | 落在瓶身轮廓外 |
|---|---|---|
| 修后（裁剪挂在不动外层） | 132 | **0** |
| 反证：把同一帧的裁剪挪回会动那层 | 511 | **379** |

图：`incident-ab-good.png` / `incident-ab-bad.png`（同一帧、只看裁剪挂在哪层；
bad 那张能直接看到液面椭圆和液体落到瓶底以下）。事故两个真实场景的定格：
`incident-scene-poke.png`（玻璃棒捅洗 → 裂纹 + 碎玻璃）、`incident-scene-oven.png`
（105 ℃ 烘烤 → 裂纹 + 器底火焰/暖光）。这两台容量瓶在这一步是**空的**（液位 0），
所以画面里本来就没有液体可露——液体层的问题只能靠上面那组对照量出来。

单测：`incident.test.ts` 新增一条结构断言（裁剪必须在器身 `<g transform>` 上、`data-i="liquid"`
上不许有 `clip-path`、矩形横向 = `liquidBox`），`liquid-clip.test.ts` 的事故用例覆盖
volumetric/flask/beaker × pour/heat/stir/poke 共 12 组。把 incident.tsx 改回旧写法，这 2 条立刻红。
