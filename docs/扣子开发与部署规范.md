# 扣子编程开发 / 部署 / AI 接入规范（chem-lab 对齐版）

> 目的：本项目**最终部署走扣子编程（code.coze.cn）**，所以本地开发从一开始就按扣子的约束写，
> 避免"本地能跑、传上去就坏"。本文分两部分：① 官方硬约束（带出处）；② 我们项目的对齐清单。
> 整理日期 2026-10-23；官方文档若有更新以此链接为准。

---

## 一、部署形态（必须贴合，不能改）

| 项 | 官方规定 | 我们的落法 |
|---|---|---|
| 构建指令 | 平台固定，**不支持修改，只能查看** | 必须能被 `npm run build` 直接构建成功 |
| 启动指令 / 端口 | 平台注入 `PORT`，部署脚本执行 `npm run start -- --port ${PORT}` | `package.json` 的 `start` 写成 **`next start`**（不写死端口，读 `PORT`），本地由 `restart-prod.ps1` 设 `PORT=3001` |
| 运行时 | Node 22 | `.coze` 里 `requires = ["nodejs-22"]` |
| 输出目录 | Next standalone | `next.config.ts` 里 `output: "standalone"`；构建后 `.next/static` 要一起带（本地重启脚本已处理） |
| 部署权限 | **仅项目所有者**可部署，且有配额 | 由项目 owner 操作 |
| 可见性 | 仅支持**公开部署** | 无需登录的公开站点；内部数据靠应用自身鉴权 |
| 服务器 | 默认 1C2G / 2 实例 / 每实例 100 并发；无流量可缩容到 0 | 我们的接口要能承受冷启动（首请求慢），不假设常驻内存缓存 |
| 域名 | 默认 `*.coze.site`，可改前缀（改了立即生效、旧域名失效） | 部署后再定 |

**结论**：构建/启动/端口这三件是平台写死的，本地必须完全一致，否则上传后必然起不来。

## 二、环境变量规范

1. **自定义变量不允许 `COZE_` 开头** —— `COZE_` 是系统变量专用前缀（官方原文）。
   → 我们的模型凭据一律用 `BOT_TOKEN` / `BOT_ID` / `LLM_API_KEY` / `LLM_BASE_URL` / `BOT_APP_ID` / `BOT_KID` / `BOT_PRIVATE_KEY`，
   代码里 `lib/plan/llm-assess.ts` 的 `env()` 同时认两套名字（扣子名优先、旧 `COZE_*` 兼容）。
2. **开发环境 / 生产环境完全隔离**：开发环境只在开发期生效；生产环境变量**只能在「发布管理」页配置**，且改完要重新部署才生效。
3. 首次部署时系统会把开发环境变量同步到部署页，可以调整后再发布。
4. 数据库：平台托管 PostgreSQL；首次部署可选「同步数据 / 只同步表结构」，**之后每次部署只同步结构变更、不同步数据**，回滚不带库。

**我们的落法**：`.env.local` 只放本地值且已 gitignore；线上值在「发布管理」按上表名字填一遍。

## 三、资源与运行时限制

| 限制 | 官方数值 | 影响 |
|---|---|---|
| 单文件上传 | **16 MB** | 大文件必须分片（每片 ≤4MB）；我们的资产都在 `public/` 静态打包，不受影响 |
| HTTP 长连接 | **300 秒**无数据传输即断（旧笔记写的 90s 已过时） | 长任务/SSE 要每 **85 秒**发一次心跳；我们的评分接口 ≤26s，无需心跳，但助教若改流式要注意 |
| 沙箱 | 3 GB 磁盘、1 小时空闲回收 | 不要往容器里写大文件；不要依赖本地文件做持久化 |
| 文件系统 | **生产容器只读**（历史踩坑） | 没有 `DATABASE_URL` 时会回落 PGlite 本地文件 → EROFS → 接口 500。**线上必须注入真 PG 连接串** |
| 资源路径 | 开发 `/workspace/project/assets`，部署后 `/opt/bytefaas/assets` | 一律用 `COZE_WORKSPACE_PATH` 拼路径，不写死 |
| 构建内存 | 平台 1C2G 起 | 我们的 `next.config.ts` 已把 `experimental.cpus` 压到 4，避免本地 build OOM |

## 四、AI 功能接入规范（扣子编程内）

### 4.1 平台内：零配置（推荐，也是"长期不用管令牌"的唯一办法）
```ts
import { LLMClient, Config, HeaderUtils } from "coze-coding-dev-sdk";

const customHeaders = HeaderUtils.extractForwardHeaders(request.headers); // 必须转发
const client = new LLMClient(new Config(), customHeaders);                 // 不用配 key
```
- `new Config()` 会从环境变量自动加载平台注入的凭据；
- 平台内部接的是**扣子托管模型**（默认 `doubao-seed-2-0-pro-260215`），**不需要 PAT**；
- 与"从外部 `api.coze.cn` 调已发布 Bot"是两码事——后者才需要 PAT（最长 30 天）。

### 4.2 本地开发：必须自己给凭据
- `extractForwardHeaders` 在本地返回空对象也不报错 → **同一份代码两处都能用**；
- 但**实测**：`new Config({ apiKey: 'pat_...' })` 调 `integration.coze.cn` 会被拒
  （`token contains an invalid number of segments` —— 该网关要三段式 JWT，不认 `pat_`）。
- 所以本地走**HTTP 通道**：`https://api.coze.cn/v3/chat` + PAT，或 OpenAI 兼容端点 + key。
  我们已封装：`lib/plan/llm-assess.ts`（HTTP）、`lib/ai/sdk-llm.ts`（SDK），
  开关 `LLM_CHANNEL=auto|sdk|http`，`auto` = 平台运行时优先 SDK、失败回落 HTTP、再失败回落本地点评。

### 4.3 调用纪律
1. SDK **只能在后端**（route handler / server action）里用，进 client 代码是硬错误。
2. `messages` 至少要有 1 条 `role: "user"`，只有 system/assistant 会校验失败。
3. 评分任务：`invoke()` 拿整段 + `temperature 0.0~0.2` + 强 system 约束 + 解析兜底；
   助教对话：`stream()` + `thinking: "disabled"` + `temperature 0.7~0.9`。
4. **SDK 没有 `response_format` / JSON 模式**：JSON 稳定性只能靠 ①system 里写死输出格式 ②剥 ``` 壳 ③校验 ④失败回落。
   我们的 `sanitizeScore` / `sanitizeDimensions` / `parseModelAnswer` 就是这一层。
5. **关掉深度思考**：同一问题实测 `thinking: enabled` 9.9s → `disabled` 5.6s（输出质量不变）。
6. 平台内流式返回 `AsyncGenerator`，要转成 `ReadableStream` 再给前端 SSE。

### 4.4 存储与数据库
- 平台内的对象存储 / 数据库都是**平台注入凭据的托管服务**，不存在"带走一份"；
- 脱离平台 = 自备 S3 兼容桶 + 自建 PG。我们已经是 Drizzle + `DATABASE_URL` 探测（裸 PG，符合要求）。

## 五、交付与协作规范

- **只支持 main 分支**做部署来源 → 本地开发在 main 上小步提交，别开长期分支。
- 代码进扣子后，由扣子 AI 继续改；因此**代码要可读、约定要显式**（我们的 AGENTS.md 就是这个作用）。
- 技能（skill）机制：项目可用官方技能 + 自定义技能（上传 `.skill` 包）；官方技能别乱删，删了扣子 AI 会报错。
- 协作模式：Agent（自动改）/ 问答（只看不动）/ 计划（先出方案再执行）；网页应用支持计划模式。
